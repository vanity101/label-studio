# Problem

单视角标注路径已闭合：overlay 可导入，点标签切段已出现在正在跑的标注页，运行时侍出入口已按 Vite 模块加载（见 `label-studio-annotation.md`、`label-studio-annotation-ux.md`、`label-studio-annotation-ux-runtime.md`）。UX 那一轮**明确不交付**右侧 Regions 拖排序：官方 Manual 拖放改的是分组（父子嵌套），没有「插到第几行」；名单显示又按创建身份或媒体开始时间排，拖完看起来像 End 下面缩进 grasp。

手册原文是：选中右侧标签，向上或向下拖，只整理名单谁在上谁在下。用户现已确认要补这一条。

本轮**叠加**在已闭合路径上，不取代、不覆盖上一轮 overlay / UX / runtime 规格、合同、eval、评审。不新开其它交互。不改多视角。不重写 Regions / 播放器 / 核心。

必须纠正：

- 拖名单 **不是** 改各段 start / end，也不是改阶段名。
- 拖名单 **不是** 改切段公式：「上一标签」仍是创建顺序里的最后一条，不是名单上的上一行。
- 禁止用改创建身份的办法换序。
- 禁止拖成父子嵌套。
- 禁止把 Vite 产物改名覆盖成 Webpack `main.js`。

# Users and Context

- **标注员**：在已贴单视角模板的任务上，按点击顺序标完若干段后，若右侧名单和想看的顺序不一致，按住某一行上下拖，只改名单排列。必须能拖到当前第一行的上面，成为新的第一行。拖到另一行身上时仍是并列换位，不要变成子节点。拖完再点顶部阶段标签切段时，起止帧仍按创建顺序算，不按刚拖出来的名单顺序算。
- **项目负责人**：仍用上一轮 overlay 建项目、贴单视角模板。本轮不改他们的建项流程，不改多视角 XML。
- **下游消费方**：时间轴结果仍是官方 `ranges` + `timelinelabels`；每段 start / end / 标签名不因拖名单而变。不发明第三种结果格式来表达名单顺序。
- **本仓库 Agent**：先写完成合同，再浅改 Outliner 拖放与显示顺序；必须独立在页面上拖一遍核验。人只确认验收，不代替 Verify。
- **人**：只确认验收。

已确认、不要再猜：

1. **范围**：只补手册里的 Regions **扁平拖排序**。只做简单单视角。尽可能最少代码。
2. **拖的语义**：右侧 Regions 上下拖，只改名单谁在上谁在下。各段 start / end 不变，阶段名不变。
3. **结构**：始终并列。禁止拖成父子嵌套（不要再出现 End 下面缩进 grasp）。拖到另一行身上 = 并列换位，不是收成子节点。
4. **插到第一行上面**：必须能把某条拖到当前第一行的上面，它成为新的第一行。不是只能在已有两行之间对调。
5. **默认 vs 拖过之后**：未拖过时，名单仍是点击 / 创建顺序，先点的在上。用户拖过之后，名单改用这次拖出来的顺序。
6. **切段公式不变**：点标签切段仍按 UX 规格。「上一标签」= 已有阶段区间里按**创建顺序的最后一条**，不因拖名单而改切段起止帧。
7. **不改创建身份换序**：禁止靠改创建身份来让名单看起来换了序。
8. **工程边界**：只浅改 Outliner 拖放 + 显示顺序。不重写 Regions / 播放器 / 核心。不改多视角 XML。不交付其它新交互。自建镜像仍是「官方镜像 + 改过的前端」。

手册仍成立、本轮不推翻：

- 细致度仍是同一条时间轴上标签多少、描述粗细。
- 预置阶段字面量仍是 `Static` / `grasp` / `Place` / `End`。
- 点标签切段、侧栏改名、顶部「废弃」、允许重叠，仍按 UX 规格。
- 运行时仍走已闭合的 Vite 模块侍出，禁止再走 Webpack 入口覆盖事故。

# Deliverables

全部落在「扁平拖排序 + 独立显示顺序 + 独立页面核验」上。不重写 Label Studio 产品，不覆盖已有规格文件。

1. **本文件**：Regions 扁平拖排序执行计划（产品层）。已有 overlay / UX / runtime 执行计划、产品摘要、合同、eval、评审一律保留原文，本轮不改那些文件来「更正」拖排序。
2. **完成合同与 eval**：由后续 Coder 写入 `docs/harness/evals/`。没有合同不改业务代码。
3. **扁平拖排序**：右侧 Regions 可上下拖；结果始终是并列名单换位；能插到当前第一行上面。
4. **显示顺序与切段解耦**：名单显示顺序可被拖放改写；切段所用的「上一标签」仍按创建顺序。二者不是同一条轴。
5. **独立核验**：Agent 必须在正在跑的单视角标注页上真的拖一遍（无头浏览器或等价），不能把「请用户拖一下」当 Verify。
6. **上一轮检查仍绿**：overlay / UX / runtime 的 Python eval 不得被本轮打红。

# Success Criteria

以下任一项不满足，本轮即未完成。核验必须由 Agent / Reviewer 独立完成。

- **拖 A 到 B 上面**：名单变成 A 在 B 上；A、B 的 start / end 与阶段名都不变。
- **拖到第一行上面**：把某条拖到当前第一行的上面后，它成为第一行；其余相对关系保持并列。
- **拖到另一行身上**：不得变成子节点（不得出现缩进父子）；结果仍是并列换位。
- **拖完再点标签切段**：切段公式仍按创建顺序取「上一标签」（创建顺序的最后一条），不按名单当前从上到下的顺序改起止帧。
- **默认顺序仍在**：从未拖过时，名单仍是点击 / 创建顺序，先点的在上。
- **不改多视角**：不改 `configs/multi-view.xml`。
- **上一轮仍绿**：`python3 docs/harness/overlays/zhiyuan-robot-video/check_overlay.py` 退出码 0；`python3 docs/harness/evals/test_robot_video_annotation.py` 全绿；`python3 docs/harness/evals/test_robot_video_ux.py` 全绿；`python3 docs/harness/evals/test_robot_video_ux_runtime.py` 全绿。
- **工程边界**：没有重写 Regions / 播放器 / 核心；没有把 Vite 覆盖成 Webpack `main.js`；没有完整 clone；自建镜像仍是官方发行版加改过的前端。

上游 Cypress / 全仓 build **不是**本轮通过条件。

硬门槛草案（写入合同时须保留）：约定的拖排序检查与上一轮 Python eval 全绿；eval 若有 pass_rate，建议 ≥ 0.8 且无 Critical。任一项不达标则本轮失败。

# Existing Building Blocks

优先复用，禁止另起一套名单产品：

- **已闭合的单视角路径**：overlay 单视角模板、点标签切段、Vite 模块侍出、正在跑的自建镜像。本轮只在这条路径上补拖排序。
- **已有默认排序**：UX 轮已把未拖过的名单做成点击 / 创建顺序、先点的在上。本轮保留它当默认，只在用户拖过之后改用拖出来的顺序。
- **官方 Outliner 拖放**：已有按住行拖动的手势。现状是改分组关系（父子），没有插入到第几行。本轮要的是同一手势的**扁平换位**，不是新做一套拖放框架。
- **官方名单显示**：现状会按创建身份或媒体开始时间排。本轮方向是 overlay 一层**独立显示顺序**，而不是改创建身份或改时间轴数据。
- **切段逻辑**：已有「上一标签 = 创建顺序最后一条」。本轮不得把它改成「名单上一行」。
- **上一轮 Python eval**：overlay / annotation / UX / runtime 仍是回归门禁。
- **Playwright（或等价无头）**：本轮独立 UI 核验入口，必须真的拖。

# High-Level Approach

方向一句话：**关掉嵌套，用独立显示顺序。** 不要用改分组、也不要用改创建身份，来假装换了行序。

1. **先合同后改**：Coder 把完成合同写入 `docs/harness/evals/`，硬门槛含「拖 A 到 B 上」「拖到第一行上面」「拖到行上仍并列」「拖完切段仍按创建顺序」、以及上一轮 Python eval 仍绿。没有合同不改业务代码。
2. **只浅改 Outliner 拖放 + 显示顺序**：拖的结果是「插到哪一行的上面 / 下面」，名单始终扁平并列。关掉拖成父子。能插到当前第一行上面。
3. **显示顺序独立于切段顺序**：名单可以记住用户拖出来的顺序；切段仍读创建顺序。默认（未拖过）继续用创建顺序，先点的在上。
4. **不碰时间轴数据**：拖放不得改 start / end、标签名、创建身份。导出形状不变。
5. **覆盖面最小化**：不重写 Regions 存储、不重写播放器、不改多视角 XML、不新开交互。自建镜像仍基于官方发行版替换前端；侍出继续走已闭合的 Vite 模块入口。
6. **独立核验后再进人**：无头打开正在跑的单视角任务，至少拖三种落点（到另一行上面、到第一行上面、到另一行身上）。Reviewer 按合同复跑。人只确认验收。

# Risks

已确认、按事故 / 延期处理，不再当未知：

- **官方 Manual 拖放 = 分组，不是插行**。若不关掉嵌套，验收时仍会出现 End 下面缩进 grasp，本轮直接失败。
- **按创建身份或媒体开始时间排序会盖掉拖放结果**。只改拖放手势、不改显示顺序，拖完会弹回。必须有独立于切段 / 创建身份的显示顺序。
- **用改创建身份换序会破坏切段**。「上一标签」依赖创建顺序；改身份等于改切段公式。禁止。
- **Vite 覆盖 Webpack `main.js` = 白屏**。本轮若再这样做，视为直接失败。
- **人点页面不是 Verify**。必须 Agent 自己在页面上拖一遍。

仍要防：

- **切段与名单耦死**：实现若让「上一标签」改读名单上一行，拖完再点标签会切错帧。合同必须把切段夹具和拖排序夹具分开断言。
- **只能对调、不能插到第一行上面**：只实现「拖到某行下面」会漏手册里的「成为新的第一行」。
- **范围膨胀**：借机重写 Outliner 树、改播放器、改多视角、或把 UX 已交付能力重做一遍。本轮失败条件是扁平拖排序未交付，不是产品清单没做完。
- **刷新后顺序是否还在**：未确认。不要发明新导出字段；当次页面顺序满足成功标准即可。
- **上一轮 eval 被误伤**：浅改显示顺序时不得把默认点击顺序、切段、侍出入口打红。
- **只改了构建产物、8080 仍是旧前端**：核验必须打正在跑的标注页，不能只看源码或 Python eval。

# Suggested Verification

完成合同由后续 Coder 写入 `docs/harness/evals/`。本轮规格不假装拖排序已绿。

建议合同至少覆盖：

- **拖 A 到 B 上面（页面）**：至少两段阶段区间；把下面那条拖到上面那条上方；名单顺序对调；两段 start / end / 名称不变。
- **拖到第一行上面（页面）**：把非第一行拖到当前第一行上方；它成为第一行；仍全部并列。
- **拖到行上（页面）**：拖到另一行身上；不得出现子节点 / 缩进；结果仍是并列换位。
- **拖完再切段**：拖乱名单后，再 seek 并点新阶段标签；新段起止仍按**创建顺序最后一条**的结束帧计算，不按名单第一行 / 上一行计算。
- **未拖过的默认**：连续点两个标签、一次都没拖，名单仍是先点的在上。
- **回归**：`check_overlay.py`、`test_robot_video_annotation.py`、`test_robot_video_ux.py`、`test_robot_video_ux_runtime.py` 全绿。
- **非目标抽查**：`configs/multi-view.xml` 相对本轮无改动；没有 Vite 文件被侍出成 Webpack `main.js`。
- **硬阈值草案**：上述拖排序与回归检查全绿；eval 若有 pass_rate，建议 ≥ 0.8 且无 Critical。嵌套、切段被拖乱、插不到第一行上面、上一轮 Python eval 变红，任一项即失败。
- **失败行为**：无法关掉嵌套或无法独立显示顺序时返回明确错误。禁止改创建身份换序。禁止改切段公式。禁止改多视角 XML。禁止把核验推给人。禁止再用 Vite 覆盖 Webpack `main.js`。禁止完整 clone、禁止重写核心。
