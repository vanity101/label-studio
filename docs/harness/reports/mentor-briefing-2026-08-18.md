# 机器人视频标注：工作汇报

当前能跑的实例：本机 `http://localhost:8080/`，自建镜像（官方 LS + 改过的前端）。

---

## 1. Harness 是怎么设计的、帮我做成了什么

### 1.1 一句话

Harness 是一套 **「人和 Agent 怎么分工、做到什么算完」** 的协作协议。人定目标和判断题；Agent 读地图、写规格、按合同改代码、自己跑检查、再让另一个 Agent 独立评审。人只做最后确认，不代替核验。

### 1.2 为什么要有它

二次开发很容易踩三个坑：

1. **还没想清楚产品就改核心**（例如把「细致度」理解成三套时间轴）。
2. **测试绿了但标注员打不开**（源码对了，正在跑的网页仍是旧前端）。
3. **把「请你点一下页面」当成验收**（人替 Agent 做了核验）。

Harness 用固定流程把这些坑挡在改代码之前、交人之前。

### 1.3 设计要点（四层文档 + 一条流水线）

仓库入口是根目录 `AGENTS.md`（Agent 地图）。约定：


| 层           | 放哪                                   | 写什么                  | 不写什么          |
| ----------- | ------------------------------------ | -------------------- | ------------- |
| 产品摘要        | `docs/harness/product-specs/`        | 能力、非目标、验收要点          | 函数名、文件补丁      |
| 本轮计划        | `docs/harness/exec-plans/active/`    | 给谁用、交付什么、成功标准、风险     | 细实现           |
| 完成合同 + Eval | `docs/harness/evals/`                | 交付物、怎么验、硬门槛、失败时禁止做什么 | 「看起来像了就算过」    |
| 评审 / 交接     | `docs/harness/reviews/`、`handoff.md` | 独立复跑结论、下一轮从哪接        | 自己写完自己宣布 PASS |


流水线（agent-builder skill）：

```text
理解需求 → 读现有代码 → Planner 写规格
        → 写完成合同（没有合同不改业务代码）
        → 按合同实现（优先复用 LS，禁止重写核心）
        → 自己跑 eval / 页面检查
        → Reviewer 只读复跑，结论落盘
        → 才交给人确认
```

硬原则：

- **叠加不覆盖**：后一轮（点标签切段、侍出入口、拖排序）叠在前一轮上，不把旧规格改成「从来如此」。
- **能写成测试的约束，不要只写在聊天里。**
- **人确认验收，不代替 Verify。**



### 1.4 它实际帮我落地了哪些功能

按轮叠加，不是一次做完：

**第 1 轮：Overlay（模板，不改 LS 内核）**

- 单视角 Labeling Config：一条视频 + 一条时间轴，阶段字面量 `Static` / `grasp` / `Place` / `End`。
- 细致度 = **同一条轴上标签多少、描述粗细**，不是三套界面。
- 整段信息（简单/中等/复杂、动作序列）用 `Choices` / `TextArea`，不另开时间轴。
- 导出仍用官方形状：时间轴是 `ranges` + `timelinelabels`。
- 多视角 XML 备着但本轮不改、不验收三路视频。

**第 2 轮：前端交互（浅改编辑器）**

- **点顶部阶段标签即切段**：第一段 1→播放头；其后 上一结束帧+1→播放头；允许重叠。不必再在轴上画。
- 右侧 Region 可改名（阶段下拉）和起止帧。
- 「废弃」与阶段标签同一条顶部栏；点了表示整视频不可用，不占一段时间轴；导出为 `choices`（`from_name=discard`）。
- 名单默认按点击/创建顺序，先点的在上。

**第 3 轮：侍出入口（标注员真正加载到改过的前端）**

- 官方镜像 HTML 仍加载 Webpack 三文件；仓库构建是 Vite hash 包。对齐方式：HTML 改为 `type=module` 加载 Vite 真实入口，**禁止**把 Vite 文件改名为 Webpack 的 `main.js`。
- 自建镜像仍是 `FROM heartexlabs/label-studio` + 改过的前端，不是新栈。

**第 4 轮：Regions 扁平拖排序**

- 上下拖只改名单谁在上谁在下，不改帧、不改名、不改切段公式。
- 禁止拖成父子嵌套；能插到当前第一行上面。

## 2. Label Studio 前端怎么分层、我们改在哪



### 2.1 先分清三块（不要把整个 `web/` 当成一块）

LS 前端在 `web/`，大致三块：

```text
浏览器
  └─ Django 吐出 HTML（登录页 / 应用壳）
        └─ LSO  apps/labelstudio     项目、数据管理、设置、路由壳
              └─ 打开一条任务时挂上
                    LSF  libs/editor     真正的标注画布（我们主要改这里）
              └─ DM   libs/datamanager  任务列表、筛选、导入
```

- **LSO**：网站外壳。登录、项目卡片、数据管理页。
- **LSF（Editor）**：标注内核。XML 配置变成可点的标签、视频、时间轴、右侧 Regions。技术栈是 **React + MST（mobx-state-tree）**。
- **DM**：任务表格。

后端 Django（`label_studio/`）管账号、保存、导出。本轮约定：**不重写核心、不大规模改 Django**。保存仍走官方 Annotation。

### 2.2 标注页是「XML → 注册表 → 模型 → 界面」

项目的 Labeling Setup 是一份 XML（我们的 `single-view.xml`）。LSF 用 **Registry** 把标签名登记成模型：


| XML 标签             | 角色                          | 代码大致位置                                  |
| ------------------ | --------------------------- | --------------------------------------- |
| `<Video>`          | 被标对象：播放器 + 播放头帧号            | `tags/object/Video/`                    |
| `<TimelineLabels>` | 控制：阶段标签栏                    | `tags/control/TimelineLabels.js`        |
| `<Label>`          | 某一个阶段字面量                    | `tags/control/Label.jsx`                |
| `<Choices>`        | 整段选项（废弃、细致度）                | 官方 Choices，不占时间轴                        |
| 右侧名单里的一段           | Region：`ranges` + 标签名       | `regions/TimelineRegion.js`             |
| 右侧 Outliner        | 名单树 / 拖放                    | `components/SidePanels/OutlinerPanel/`  |
| 选中后的详情             | 改名、改帧                       | `DetailsPanel/TimelineRegionEditor.tsx` |
| 名单顺序               | `RegionStore.sortedRegions` | `stores/RegionStore.js`                 |


点击一条阶段标签时，官方默认是「先选中标签，再去时间轴上点一下或拖一下」——所以第一版只贴 XML 时，点 Place 只会保持选中，区间变成当前帧的单帧。我们把 **TimelineLabels 的点击**改成：按公式算出 start/end，立刻 `addTimelineRegion` + `setRange`。

切段公式（帧从 1 起算）单独抽在 `timelineClickToSpan.js`，方便 Python / bun 两边对照，避免只写在聊天里：

- 还没有上一段、播放头 N → `1 … N`
- 上一段结束 N、播放头 M > N → `N+1 … M`
- 上一段结束 N、播放头 M ≤ N → 允许重叠，`M … N`
- 「上一标签」= **创建顺序最后一条**（看 `ouid`），不是名单上的上一行



### 2.3 一次标注在内存里长什么样

```text
Annotation（这一次提交草稿）
  ├─ objects：Video 等（有 currentFrame）
  ├─ names：XML 里 name="videoLabels" 等
  └─ regionStore
        ├─ regions[]：每一段 TimelineRegion（ouid = 创建身份）
        ├─ sortedRegions：名单显示顺序（可被拖过的 outlinerOrder 覆盖）
        └─ asTree：画成树；时间轴段我们改成始终扁平，不再挂父子
```

导出时时间轴仍是官方字段，没有发明第三种格式：

```json
{
  "from_name": "videoLabels",
  "type": "timelinelabels",
  "value": {
    "ranges": [{ "start": 1, "end": 42 }],
    "timelinelabels": ["Place"]
  }
}
```

废弃是另一条整段 `choices`，不是一段 `ranges`。

### 2.4 页面怎么把「我们改过的 JS」送到浏览器

这是二次开发最容易忽略的一层：

- 仓库里 `bun run build` 打出 **Vite** 包：`main-哈希.js` + 一堆 `src-哈希.js`。
- 官方 Docker 镜像里的 Django HTML 默认加载 **Webpack** 三件套：`runtime.js` + `vendor.js` + `main.js`。
- 两套对不上：切段写进了 Vite 包，标注员却在执行官方 Webpack。

正确对齐（方向 A）：改官方 `base.html`，用 `type="module"` 按 manifest 加载 Vite 的真实 hash 名。Django 还要从 `STATIC_ROOT/js/manifest.json` 读入口；官方镜像的 `BASE_DIR` 在 `label_studio/core`，所以文件必须放到 `core/static_build/js/`，放到别的目录等于没换。

**禁止**：把 Vite 的 ESM 文件复制成 Webpack 的 `main.js`——官方页仍当经典脚本执行，结果是白屏。

## 3. 第一版 MVP 的问题，以及后来怎么收

这里的「第一版 MVP」指：**先只靠官方 LS + 一份 XML overlay 跑起来**，以及紧接着「源码已改、eval 已绿、但标注员路径未闭合」的那一截。问题按「产品理解 → 模板检查 → 交互 → 侍出 → 名单拖放」排列。

### 3.1 产品理解：把细致度做成三套时间轴


|        |                                                                                     |
| ------ | ----------------------------------------------------------------------------------- |
| **问题** | 早期把「简单 / 中等 / 复杂」理解成三套并列控件（轨迹级、段级、帧级各一条时间轴）。手册原文不是这样。                               |
| **后果** | 会做出第二、第三条 TimelineLabels，和手册倒水示例（同一轴上标签变多、描述变细）相反。                                  |
| **解决** | 作废旧理解。产品摘要写死：一条视频、一条时间轴、一套区间标签。细致度整段用 Choices，不另开轴。Eval 负例：第二套 TimelineLabels 必须失败。 |




### 3.2 模板检查：把「示范夹具」当成「所有合法标注」


|        |                                                                                                             |
| ------ | ----------------------------------------------------------------------------------------------------------- |
| **问题** | 检查脚本一旦看到时间轴结果，就强制四个阶段标签齐全、必须有两段 Static、必须带整段字段。简单档本来就可以少标几段。官方 Export 整包（task 数组）也被同一套规则误杀。                 |
| **后果** | 合法的部分标注、仅时间轴、官方导出 JSON 对不上检查；README 按字面「导出后跑脚本」做不通。                                                         |
| **解决** | 拆成「夹具完整性」和「标注形状」：空 result、只有整段、部分区间、相交都允许。README 写清：Export 选 JSON；对账读 `annotations[].result`；不要把真实导出丢给夹具检查。 |




### 3.3 只改 XML：点标签仍是官方「先选再画」


|        |                                                                              |
| ------ | ---------------------------------------------------------------------------- |
| **问题** | Overlay 只能规定「有哪些标签」。点击行为仍是：点 Place → 标签保持选中 → 再在轴上点一下 → 得到当前帧单帧（例如 132–132）。 |
| **后果** | 模板能导入、手册字面量都在，标注员体感仍是官方交互。                                                   |
| **解决** | 允许浅改 LSF：`handleLabelClick` 按公式切完整区间并出现在 Regions，然后取消选中。合同把切段公式写成硬门槛。        |




### 3.4 废弃：位置不对、还曾做成时间段的风险


|        |                                                                                                                                                                                                      |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **问题** | 第一版模板把废弃/异常/abnormal 放在视频下方整段栏。产品只要一个「废弃」，且与阶段标签同一条顶部栏；点击 = 整视频不可用，不能再标、不能再改已有区间。若做成 TimelineLabels，导出就会变成又一段 `ranges`。                                                                              |
| **解决** | XML 里「废弃」是 `Choices name="discard"`，和 TimelineLabels 同一条 flex 栏、在 Video 之前。点废弃不切段；导出是 `choices`。切段启用不再死磕 `names.get("discard")` 一种 Map 键（加了 `resolveNamedTag`，因为 MST 里 key 可能是 `name@annotationId`）。 |




### 3.5 Eval 绿了就交给人点：核验缺口


|        |                                                                                                                      |
| ------ | -------------------------------------------------------------------------------------------------------------------- |
| **问题** | UX 源码评审 PASS，Python eval 全绿，但检查不打开浏览器、不点 Place、不读 Regions。合同还把 `docker build` 标成环境问题、不判失败。Agent 一度请用户强制刷新、自己点 Place。 |
| **后果** | 人替 Agent 验收；标注员路径其实没闭合。违反「人只确认、Agent 跑检查」。                                                                           |
| **解决** | 单开运行时合同：首页非白屏、实际加载的 JS 含切段逻辑、Playwright 必须点 Place。未独立核验、未写评审，不交人。                                                    |




### 3.6 侍出错位：改了源码，网页还在跑官方 Webpack


|        |                                                                                                  |
| ------ | ------------------------------------------------------------------------------------------------ |
| **问题** | 自建镜像拷了 Vite dist，官方 HTML 仍加载 `runtime.js + vendor.js + main.js`。切段打在 Vite 包里，标注员执行的是发行版 Webpack。 |
| **后果** | 仓库里点标签会切段，8080 上点 Place 仍保持选中、区间单帧。                                                              |
| **解决** | 方向 A：官方 HTML 改为 `type=module` + manifest 指向 Vite hash 入口。Dockerfile 仍 `FROM` 官方镜像。               |




### 3.7 用 Vite 冒充 Webpack 的 `main.js` → 白屏


|        |                                                                                                    |
| ------ | -------------------------------------------------------------------------------------------------- |
| **问题** | 为了让旧 HTML 加载到新包，把 `main-哈希.js` 复制成 `main.js`。官方页按**经典脚本**执行 ESM，应用起不来，`http://localhost:8080/` 空白。 |
| **后果** | 可用性事故。从镜像层恢复官方 `main.js` 后页面能开，但切段仍不在侍出入口。                                                         |
| **解决** | 合同写死禁止再覆盖。事故评审 FAIL 文件保留，不假装没发生。正确做法见 3.6。                                                         |




### 3.8 Manifest 放错目录：登录页正常，登录后再次空白


|        |                                                                                                                                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **问题** | 登录页走另一套模板，不加载应用 JS，所以看起来正常。登录后 `base.html` 用 `manifest_asset` 解析入口；官方镜像 `STATIC_ROOT` 在 `label_studio/core/static_build`。Manifest 曾拷到错误路径，解析失败，回退成 `/react-app/main.js`（Webpack），module 脚本加载 Webpack 包 → 又白。 |
| **解决** | Manifest 拷到 `core/static_build/js/manifest.json`。核验必须看**登录后** HTML：应用脚本应是 `type=module` 的 `/react-app/main-哈希.js`。                                                                                           |




### 3.9 拖名单：官方 Manual 是「挂成父子」，不是「换行序」


|        |                                                                                                                                              |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| **问题** | 手册「选中后上下拖」是扁平换位。LS 右侧 Manual 拖放改的是 `parentID`（分组树）。拖 grasp 到 End 上会缩进成子节点，且几乎无法放到第一行上面。名单显示还按 `ouid` 排，只改拖放手势会弹回。若改 `ouid` 换序，会打乱切段用的「上一标签」。 |
| **后果** | 看起来像合并，不是并列排序。                                                                                                                               |
| **解决** | 时间轴 Region：关掉嵌套；`outlinerOrder` 独立显示顺序；拖到行上沿 = 插到上面（含第一行）；切段仍读创建顺序。不发明新导出字段；当次页面顺序即可。                                                        |




### 3.10 工程边界上还踩过的小坑（一并记下）

- **根目录** `docker-compose.yml` **含** `build: .`：浅克隆下不要用它起全栈，应用官方镜像 + overlay Dockerfile。
- **项目里存的仍是旧 XML**：换镜像不会改数据库。点标签切段依赖当前 Labeling Setup 已贴 `single-view.xml`（顶部有「废弃」）。
- **Service Worker / 缓存**：换前端后旧 `main.js` 可能还在浏览器里；核验看网络请求，不把「请强刷」当修复。
- **生产 minify 会吃掉函数名**：合同若写死侍出 JS 必须含 `nextClickSpan` 字面量，打包后可能找不到。改为锁 MST 动作名 / 模型名，并用页面行为锁住。

## 5. 给自己复述用的三句话

1. **Harness** 是「先规格、再合同、再改代码、再独立评审」；它逼我把切段公式、禁止白屏、禁止嵌套写成能跑的检查，而不是聊天记录。
2. **LS 前端** 外壳是 LSO，标注是 LSF；XML 变成 MST 模型；我们只浅改 TimelineLabels 点击、Region 显示顺序和官方 HTML 如何加载 Vite 包。
3. **第一版 MVP** 能贴模板，但不能当智源交互；真正的坑是「源码/eval 绿 ≠ 浏览器在跑那份包」，以及官方拖放是树不是名单。
