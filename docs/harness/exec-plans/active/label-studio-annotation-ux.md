# Problem

上一轮已交付可导入的 overlay，能在官方 Label Studio 发行版上对机器人视频做时间轴阶段标注（见 `docs/harness/exec-plans/active/label-studio-annotation.md`）。那一轮**明确不改**前端内核：标注员仍要先点标签再去时间轴上画区间；右侧 Regions 能改起止帧但不能改名称；列表没有「按点击顺序」的默认排序，且 Manual 下仍无法拖；废弃 / 异常 / `abnormal` 在页面下方单独一栏（overlay 里是整段 Choices）。

本轮用户已确认：**允许改 Label Studio 前端交互**（浅克隆 `web/` 或仅编辑器相关路径，基于官方镜像自建镜像），不重写整个栈。目标是让标注端接近手册与智源生产界面：点标签即切段、侧栏能改名、列表默认按点击顺序、废弃与阶段标签同一条顶部栏且不占时间轴区间。

**本轮叠加在上一轮 overlay 规格之上，不取代它。** 上一轮「初步能跑 overlay」的模板、导出形状、阶段字面量、一条时间轴、非整段当第二条轴等约束全部仍有效。本轮不要覆盖、不要重开「只改 XML overlay」那条路。

必须纠正：

- 不要再做成三套时间轴。
- 不要把废弃做成又一段 Static / grasp 那样的时间轴区间。
- 不要完整 clone 整个上游大仓。
- 不要写死 Django 大规模改造；后端只在「不改就无法保存新交互结果」时作为风险，不当成本轮默认交付。

# Users and Context

- **标注员**：打开一条单视角机器人视频任务，把播放头停在阶段结束处，点顶部阶段标签即生成该区间并出现在右侧 Regions；选中 Region 后改名称和起止帧；列表默认按自己点击标签的先后排列；视频不可用时在**同一条顶部标签栏**点「废弃」，整条视频作废且不能再标阶段。
- **项目负责人**：仍用上一轮 overlay 建项目；本轮会同步模板（废弃从下方整段栏挪到顶部栏）。不要求他们改账号体系或领取任务流程。
- **下游消费方**：时间轴结果仍走官方 Annotation 形状（`ranges` + `timelinelabels`）；整视频「废弃」必须能和区间结果区分，可复用现有整段字段语义。
- **本仓库 Agent**：本轮可以浅克隆前端并自建镜像；没有完成合同仍不得改业务代码。禁止完整 clone、禁止重写播放器 / 时间轴内核、禁止把手册没有的质检写成产品规则。

已确认的产品事实（不要再猜）：

1. **范围**：改前端交互，不是只改 XML overlay；允许浅克隆 `web/`、自建 Docker 镜像；不重写整个栈。**只做简单单视角。**
2. **点标签切段**：从**上一标签结束帧 + 1** 到**当前播放头**；第一个阶段标签从**第 1 帧**到播放头。点标签即生成该区间并出现在右侧 Regions。不再要求先点标签再去时间轴上画。「上一标签」= 已有阶段区间里按**点击 / 创建顺序的最后一条**（与按开始帧排序后的最后一条碰巧一致时不必区分；不一致时以点击顺序为准）。
3. **侧栏编辑**：起止帧已经能改；本轮选中 Region 后还要能改名称（对标智源生产界面 Selection Details 里的标签名下拉，选项为当前项目阶段字面量）。
4. **排序默认**：Regions **默认按点击标签的顺序**（创建 / 点击顺序），**先点的在上**。不是按视频开始帧排序。
5. **废弃**：顶部只放一个「废弃」，与阶段标签同一条标签栏，不要在页面下方单独一栏。点击表示**当前视频有问题、不可用**：**停止对本视频的标注**——不能再标阶段，也不再改已有区间（改名 / 改帧）。已有区间保留在列表里供查看。不占一段时间轴区间，不新增 `timelinelabels` 时间段。不要「异常」「abnormal」。
6. **重叠**：允许。播放头早于上一标签结束帧时点新阶段标签，不拒绝、不自动截断。M > 上一结束帧 N 时仍是 start=N+1、end=M；M ≤ N 时新段为上一结束帧与播放头之间的闭区间（start=M，end=N），与上一段时间重叠。
7. **Manual 拖拽改列表**：**本轮不做**。用户未理解该交互，未确认需要。默认只按点击顺序排列。说明见 Risks。

手册仍成立、本轮不推翻的上下文：

- 细致度 = 同一条时间轴上标签多少、描述粗细，不是三套界面。
- 预置阶段字面量保持手册大小写：`Static` / `grasp` / `Place` / `End`。下一标签开始帧默认 = 上一标签结束帧 + 1。
- 区间**允许重叠**（用户已确认）。本轮不发明自动裁剪 / 硬互斥。
- 手册「右侧按画面播放顺序从上到下」是质检注意事项；本轮产品默认是**点击顺序**。标注员按播放推进点击时，二者通常一致。
- 手册「选中标签，向上或向下拖动」是智源原文；用户未理解「只改列表顺序、不改帧」，本轮**不交付拖拽调序**。需要时另开确认。

# Deliverables

全部落在「交互规格 + 浅克隆前端改动 + overlay 同步 + 自建镜像」上，不重写 Label Studio 产品。

1. **本文件**：前端交互执行计划（产品层）。
2. **稳定摘要**：`docs/harness/product-specs/zhiyuan-robot-video-ux.md`。上一轮摘要 `zhiyuan-robot-video-annotation.md` 仍有效。
3. **时间轴标签点击切段**：点顶部阶段标签 → 生成区间 → 出现在 Regions。第一个：start=1、end=播放头；其后：start=上一标签结束帧+1、end=播放头。
4. **侧栏改名**：选中 Region 后可改标签名（下拉切换阶段字面量），且仍可改 start / end。
5. **Regions 默认点击顺序**：列表顺序与点击 / 创建顺序一致，先点的在上。不交付 Manual 拖拽调序。
6. **标签栏布局**：仅「废弃」与阶段标签同一条顶部栏；点击为整视频不可用，不能再标阶段，不占时间段。不要异常 / abnormal。细致度（简单 / 中等 / 复杂）与动作序列文本仍是整段信息，本轮不要求搬进顶部阶段栏。
7. **浅克隆 / 自建镜像约束**：只浅克隆 `web/`（或仅编辑器相关路径），基于官方镜像打自建镜像替换发行版前端。禁止完整 clone 上游大仓，禁止从零重写整个栈。
8. **overlay XML 同步（必须有，但不是本轮唯一交付）**：把「废弃」从当前单视角模板下方整段异常 Choices 挪到与阶段标签同一条顶部栏；去掉「异常」「abnormal」作为本轮废弃交互。导出上整视频废弃仍与 `ranges` 区间可区分。不要把 overlay 同步当成「只改 XML 就完成交互」。
9. **完成合同与 eval**：由后续 Coder 写入 `docs/harness/evals/`。本轮规格只写 Suggested Verification。合同未写之前不改 `web/` / 镜像 / overlay 实现。

# Success Criteria

以下任一项不满足，本轮即未完成。帧号与手册一致，从 1 起算。

- **切段（第一段）**：视频停在第 N 帧，点第一个阶段标签 → Regions 出现一段，start=1，end=N，标签名为所点字面量。
- **切段（其后，不重叠）**：再 seek 到第 M 帧（M > N），点第二个阶段标签 → 新段 start=N+1，end=M。不必再去时间轴上画。
- **切段（重叠）**：再 seek 到第 M 帧（M ≤ N），点第二个阶段标签 → 不拒绝；新段 start=M，end=N，与上一段时间可重叠。
- **侧栏**：选中任一阶段 Region，能改 start / end，并能用下拉把名称切换为当前项目已有阶段字面量（至少含 `Static` / `grasp` / `Place` / `End`；Visual 里后加的描述标签同样可被选）。改名不偷偷改起止帧；改帧不偷偷改名。
- **默认排序**：Regions 列表顺序与点击 / 创建顺序一致，**先点的在上**。不得默认按视频开始帧重排。不验收拖拽调序。
- **废弃栏位置**：仅「废弃」出现在顶部，与阶段标签同一行 / 同一条标签栏，不在页面下方单独一栏。没有「异常」「abnormal」。
- **废弃语义**：点「废弃」**不**新增 `timelinelabels` 时间段；整条视频标记为有问题、不可用；之后不能再标阶段、不能再改已有区间的名或帧（列表仍可见）。导出里能与区间结果区分（可复用现有整段字段语义）。仍须能 **Submit** 把废弃结果存下来。
- **导出形状**：时间轴仍是官方 `ranges` + `timelinelabels`；不发明第三种结果格式。
- **一条时间轴**：没有第二、第三条时间轴冒充细致度或冒充废弃。
- **工程边界**：不把整个 Label Studio 重写成新产品；不完整 clone 上游大仓；自建镜像是「官方镜像 + 改过的前端」，不是新栈。
- **叠加关系**：上一轮 overlay 的阶段字面量、头尾 Static、细致度整段字段、示例任务约定仍然可用；本轮不得为做交互而拆掉上一轮已验收的配置合法性。

# Out of Scope

- 账号 / 权限 / 领取任务 / 「一题一人」的系统强制。
- 自动质检引擎、帧边界对错判定、发明手册没有的质检规则或动作词表。
- 完整 clone 上游大仓；从零自研播放器或整套时间轴。
- ML Backend 预标注、自动切段。
- **多视角**：本轮只做简单单视角。不改多视角模板、不验收三路视频。
- Django / 后端大规模改造（默认不做）。仅当新交互结果无法用现有保存 / 导出形状落地时，才允许最小后端改动，且须先升级合同。
- 覆盖或作废上一轮 overlay 规格、合同、eval、复审结论。
- 把细致度（简单 / 中等 / 复杂）或动作序列文本改成时间轴区间。
- 把废弃做成 Static / grasp 那样的 `ranges`。
- 「异常」「abnormal」作为本轮废弃交互（用户只要一个「废弃」）。
- Manual 拖拽改 Regions 列表顺序（用户未理解、未要求交付）。

# Existing Building Blocks

优先复用，禁止另起一套标注产品：

- **官方 Video + TimelineLabels**：一条视频、一条时间轴、阶段区间仍是 `ranges` + `timelinelabels`。
- **现有 overlay**：`docs/harness/overlays/zhiyuan-robot-video/` 单视角模板（预置 `Static` / `grasp` / `Place` / `End`，下方现有整段细致度 / 动作序列 / 异常 Choices）。本轮改的是点击行为、侧栏、排序、废弃栏位置，不是重做词表。
- **官方发行版与本机环境**：Docker / Colima 已能跑官方镜像；仓库 `docker-compose.yml` 在浅克隆下仍不要当成「从本仓完整源码构建全栈」的入口。
- **智源手册**：点标签栏增加标签、右边栏删除 / 改帧与名称、选中后上下拖动、提交。
- **智源生产界面**：Selection Details 已能改名（标签名下拉）+ 改帧。本轮对标这个交互，不对标另做一套详情面板产品。
- **上一轮导出约定**：整段 `choices` / `textarea` 与时间轴结果分开读。整视频废弃可继续走整段语义，只是**视觉上**进同一标签栏。

# High-Level Approach

1. **浅克隆编辑器，不完整 clone**：只取 `web/`（或仅编辑器相关路径），在官方 Label Studio 镜像之上替换前端，打出自建镜像。不要完整 clone 上游大仓，不要重写后端与播放内核。
2. **改时间轴标签点击行为**：点阶段标签 = 按「上一标签结束帧 + 1 → 播放头」（第一段为 1 → 播放头）生成完整区间，并立刻出现在 Regions。不再走「先选标签再在轴上画」作为主路径。
3. **改 Outliner 默认排序**：默认列表 = 点击 / 创建顺序，先点的在上。不实现拖拽调序列表。
4. **侧栏改名**：选中 Region 后，Selection Details（或发行版等价侧栏）提供阶段字面量下拉，与已有起止帧编辑并存。
5. **标签栏只加「废弃」**：与阶段标签同一条顶部栏；点击 = 视频有问题，停止标注（不能再标阶段、不能再改已有区间）；不是一段时间轴区间。仍可提交。
6. **自建镜像替换官方前端**：日常跑自建镜像验证交互；不要要求标注员在稀疏工作区从源码起全栈。
7. **overlay XML 同步**：模板与新标签栏布局一致（废弃离开页面下方单独 Choices 栏）；导出仍区分区间与整视频标记。细致度、动作序列仍为整段，留在非时间轴区域。
8. **先合同后实现**：Coder 把完成合同写入 `docs/harness/evals/` 后再改前端 / 镜像 / overlay。Reviewer 按合同审查交互与导出形状，不接受「界面看起来像了」。

# Risks

已由用户确认、不再当未知：

- **点了废弃**：视频有问题，**停止对本视频的标注**——不能再生成新阶段区间，也不能再改已有区间的名 / 帧。已有区间保留可见。仍可提交。
- **只要一个「废弃」**，不要「异常」「abnormal」。
- **允许重叠**：播放头早于上一结束帧时仍可点出新段，不拒绝、不截断。
- **不交付 Manual 拖拽调序**：用户未理解该交互，未要求交付。

仍为未知、禁止编造：

- （无。多视角本轮明确不做。）

**Manual 拖拽改列表是什么（给实现的人看，本轮不做）：**  
右侧 Regions 是一份名单。官方界面有 Manual / By Time 等排序。所谓「拖拽改列表」= 按住名单里的某一行上下挪，**只改这几行谁在上谁在下**，**不改**每一段在视频里的开始/结束帧。例如先点了 grasp 再点 Place，名单是 1 grasp、2 Place；拖完变成 1 Place、2 grasp，但时间轴上两段的帧数不变。这和「点标签切段」「默认按点击顺序」不是同一件事。用户未理解且未要求交付，本轮不做。

其它工程风险（已定性，仍要防）：

- **旧「三套时间轴」误解回流**；或把废弃做成又一段 `ranges`。
- **完整 clone / 全栈重写**：工作量会撑破本轮。浅克隆范围必须守住。
- **后端保存缺口**：若改名、点击切段、整视频标记与区间并存后，官方保存 / 导出吃不下，这是风险点，不是默认去改 Django。先证明现有 Annotation 形状不够，再开最小后端合同。
- **稀疏工作区与镜像漂移**：自建镜像必须可复现（基于明确的官方镜像标签 + 浅克隆前端改动），避免「只有某台机器能跑」。
- **overlay 与前端布局不一致**：只改前端不改 XML，或只挪 XML 不改点击行为，都算本轮失败。
- **字面量大小写**：阶段标签仍是 `Static` / `grasp` / `Place` / `End`；整视频标记字面量是「废弃」。不要改成异常 / abnormal / 另一套同义词。

# Suggested Verification

完成合同由后续 Coder 写入 `docs/harness/evals/`。本轮规格不假装已有 eval 绿结果。

建议合同至少覆盖：

- **切段夹具 / 手工冒烟**：播放头 N 点第一标签 → start=1、end=N；再 M（M>N）点第二标签 → start=N+1、end=M；Regions 立即出现对应段。再 seek 到 K≤N 点第三标签 → 不拒绝，新段与上一段可重叠（start=K，end=N）。
- **侧栏**：选中 Region 可改名（下拉阶段字面量）和 start / end；保存后再打开或导出，名称与帧一致。
- **排序**：连续点三个不同阶段标签，列表从上到下 = 点击先后（先点的在上），不是按 start 帧排序。不测拖拽调序。
- **废弃**：顶部仅「废弃」与阶段标签同一栏；点击后导出无新的废弃 `timelinelabels` 区间；有整视频不可用标记；之后点阶段标签不得再新增区间；已有区间仍在但不可再改名 / 改帧；仍可提交。
- **导出**：时间轴条目仍为官方 `ranges` + `timelinelabels`；整视频标记与区间分条。
- **overlay**：单视角模板不再把废弃单独放在页面末尾一栏；仍预置四阶段字面量；没有第二套时间轴。不改多视角 XML。
- **工程**：变更集不含完整上游 clone；镜像构建说明基于官方镜像 + 浅克隆前端；不出现「重写整个 Label Studio」的目录级替换。
- **硬阈值草案**：约定的交互 / 导出 / overlay 检查全绿；eval 若有 pass_rate，建议 ≥ 0.8 且无 Critical。任一项不达标则本轮失败。
- **失败行为**：无法完成时返回明确错误；禁止编造未知项里的质检规则；禁止把废弃写成时间段；禁止完整 clone。
