# Problem

智源标注平台要对机器人操作视频做时间轴阶段标注，并按任务要求选择不同细致度。手册里的平台**本身就是 Label Studio**（设置 → 标签设置 → Code / Visual、Tasks、提交）。本仓库还没有一份按手册原文落地的 overlay：可导入的时间轴模板、任务约定、导出约定、以及能在官方发行版上复现的启动说明。

**必须纠正的旧误解（上一版规格作废）：** 旧计划把「同一视频三档细致度」理解成三套并列控件——轨迹级 `Choices` / `TextArea` + 段级 `TimelineLabels` + 帧级另一组时间轴。手册原文不是这样。三档细致度 = **同一条时间轴、同一套区间标签**；细致度越高，标签数量越多、描述越细。倒水示例：

- 简单：抓住水瓶-倒水-放在桌上
- 中等：抓住水瓶-将水瓶抬起-倒水-放在桌上
- 复杂：带「用右手」等主语，步骤更多（抓住 → 抬起 → 倒水 → 收起摆正 → 放桌上）

本轮不是发明新标注内核，也不是在稀疏工作区补齐上游源码。目标是：**用官方 Label Studio 发行版（Docker / 已安装实例），导入本仓库 overlay 后，标注员能对一条机器人操作视频做时间轴标注并提交导出**——初步能跑起来。

手册全文已在仓库，不再沿用旧 handoff「只读到登录与标注规则两节」的前提。管理端、领取任务、账号治理已读到，本轮标为后续，不假装没读到。

# Users and Context

- **标注员**：打开一条机器人视频任务，在同一条时间轴上标阶段区间，按播放顺序整理右侧标签，完成后提交。不在多个项目、多套时间轴之间跳转来表达「细致度」。
- **项目负责人**：用起步模板建项目，按本任务动作在 Visual 里加描述，按模型组改帧率，导入符合约定的任务。
- **下游消费方**（训练 / 转换 / 对账）：从官方导出还原每段起止与标签名；整段字段（细致度、动作序列文本、异常标记）与时间轴结果分开读。
- **本仓库 Agent**：只做 harness overlay、操作说明、完成合同与 eval；没有合同不改业务代码，也不改 `label_studio/` / `web/` 内核。

产品事实（只写手册已写清的，不编造未写细则）：

**时间轴阶段标签（字面量保持手册大小写）：**

- `Static`：从第一帧到机械臂未触动之前；以及机械臂收回不动之后到视频最后一帧（头尾各可有一段 Static）。
- `grasp`：机械臂完全抓住物品、未抬起之前。
- `Place`：机械臂将物品放下，爪夹完全松开。
- `End`：做完最后一个动作，机械臂收到不动状态的这段区间。

下一标签开始帧默认 = 上一标签结束帧 + 1。

**左右臂：**

- 一般情况下各标签帧数不重合。
- 不允许重叠：把两个动作合并进一条英文描述，中间用 `and` 连接。
- 允许重叠：从「趋向物体到抓紧物体」这段去标；是否允许由任务决定，先确认再标。
- 本轮产品：配置不要做硬互斥或自动裁剪；说明里写清「默认不重叠，特殊任务才允许」。

**手册已有代码模板（高层复用，不当函数实现）：**

1. **单视角**：一个 `Video` + 一条 `TimelineLabels`；`frameRate` 可按模型组改为 10 / 15 / 25 / 30（手册单视角示例为 30）。
2. **2–3 视角**：多个 `Video`（手册示例字段为 top / left / right），主视角挂时间轴，侧视角可隐藏时间轴；镜头字段名以数据包为准，不一致就改模板字段后保存。

后台加标签：Code 贴模板后切 Visual，按本任务动作加描述。标注端已有增加 / 删除 / 修改 / 移动标签、逐帧看、拖时间轴、提交——复用，不重写。

**易错与注意事项（本轮写进说明，不做自动质检引擎）：** 贴错 / 漏选 / 多选 / 漏交；分割帧靠前或靠后；尾帧应落到最后一帧；标签尽量不重合；一题一人标；过长或不完整时中文标「废弃」「异常」，英文标 `abnormal`；同一视频两段重复动作则两段都标，第一段复位放进该段的 `End`；标签不适用就反馈加标签，不硬改视频；右侧标签按播放顺序从上到下。

# Deliverables

本轮交付全部落在 overlay，不改 Label Studio 核心：

1. **单视角起步模板（必须）**：一条 `Video` + 一条 `TimelineLabels`，预置 `Static` / `grasp` / `Place` / `End`。可再加**整段**控件：细致度（简单 / 中等 / 复杂）+ 动作序列文本 + 异常标记（废弃 / 异常 / `abnormal`）。不要再做「三套时间轴」。
2. **2–3 视角模板（建议第二份配置）**：结构对齐手册（主视角挂时间轴、侧视角可隐藏时间轴）。初步版保证结构正确即可，不强制本机播三路视频。镜头字段名写成可对照数据包替换的约定，不把某一数据包的字段写成唯一真相。
3. **示例任务 JSON + 导入约定**：至少一条单视角示例（占位或可访问样例视频）；写清视频字段、恒定帧率、MP4 / H.264 建议。
4. **导出约定**：时间轴结果用官方 `ranges` + `timelinelabels`；整段字段单独区分；不发明新结果格式。
5. **短操作说明**：对照手册——建项目、贴模板、按需加标签、导入任务、标注、提交、导出。写明浅克隆下用官方镜像跑，不完整 clone。
6. **可选种子 / 检查脚本（高层）**：用现有 API 建项目，或校验配置 / 示例 JSON 形状。不要写成必须改 Django 内核。
7. **完成合同与 eval**：写入 `docs/harness/evals/`，覆盖下方成功标准中的可验收项。合同未写之前，不改 overlay 实现，更不改 `label_studio/` / `web/`。

稳定产品摘要见 `docs/harness/product-specs/zhiyuan-robot-video-annotation.md`。旧摘要 `video-three-granularity-annotation.md` 已标明作废，不得再当需求源。

# Success Criteria

以下任一项不满足，本轮即未完成：

- 配置可被 Label Studio 当作 Labeling Config 使用（XML 结构合法，含 `Video` + `TimelineLabels`）。
- 预置标签字面量包含 `Static`、`grasp`、`Place`、`End`。
- 同一视频任务上能标多个时间轴区间；头尾都可以是 Static。
- 导出能还原每段 start / end 与标签名。
- 细致度是「同一时间轴上标签多少 / 描述粗细」，不是三个独立标注界面。
- 不修改 `label_studio/` / `web/` 内核。
- 有一份能跟着做的启动说明，使「初步能跑」可复现（Docker 或等价发行版）。

# Out of Scope

手册已读，但是本轮不做：

- 自动质检引擎、帧边界对错判定、强制互斥 / 自动裁剪重叠区间。
- 账号 / 权限 / 领取任务 / 「一题一人」的系统强制（手册第四、三章管理端已读，标为后续）。
- 重写核心、完整 clone、自研播放器或时间轴。
- ML Backend 预标注、自动切段。
- 把手册截图 / 培训视频做成产品功能。
- 为每个真实任务预置完整动作词表（手册要求按任务在 Visual 里加描述，本轮只预置阶段标签）。

# Existing Building Blocks

优先复用，禁止另起一套标注内核：

- **手册模板本身**：单视角、2–3 视角的 Labeling Config 骨架；后台 Code → Visual 加标签的流程。
- **Label Studio 标注配置**：`Video`、`TimelineLabels`、整段 `Choices` / `TextArea`。
- **现有对象与接口**：Project / Task / Annotation / Export；官方导出形状（时间轴为 `ranges` + `timelinelabels`）。
- **官方发行版**：`heartexlabs/label-studio` Docker 镜像；仓库已有 `docker-compose.yml`（浅克隆下优先拉官方镜像，不在本机从源码构建）。
- **标注端已有能力**：增删改移标签、逐帧、拖时间轴、提交。

本地工作区是浅克隆 / 稀疏检出，`label_studio/` 与 `web/` 源码不在工作区。实现与验收对照官方发行行为与手册模板，不猜测稀疏检出里不存在的代码。

# High-Level Approach

1. **Overlay，不是新内核**：配置、示例任务、导入导出约定、短说明、可选检查脚本、合同 / eval 放在 `docs/harness/`（及合同约定的 overlay 目录）。不改上游核心路径。
2. **一条时间轴表达阶段与细致度**：阶段用同一套 `TimelineLabels`（预置 `Static` / `grasp` / `Place` / `End`）。细致度用整段选择记录「本任务按简单 / 中等 / 复杂来标」，真正的粗细体现在同一轴上标签数量与描述文本，而不是再挂两套时间轴。
3. **整段与区间分开**：异常标记、动作序列文本挂整段；区间结果只走官方时间轴结果。下游按控件语义区分，不发明第三种结果格式。
4. **重叠只写规则，不写引擎**：默认不重叠；特殊任务允许时由标注员按手册处理。配置不硬互斥、不自动裁剪。
5. **帧率与镜头当配置，不当代码分支**：单视角默认按手册示例 30，可改为 10 / 15 / 25 / 30；多视角字段以数据包为准。错位视为数据 / 配置问题。
6. **先合同后实现**：Coder 先把完成合同写入 `docs/harness/evals/`，再落 overlay。Reviewer 按合同审查，不接受「配置看起来能用」的自我表扬。
7. **可复现的「初步能跑」**：操作说明以官方 Docker（或已安装发行版）为准：建项目 → 贴单视角模板 → 导入示例 → 标多段（含头尾 Static）→ 提交 → 导出对账。

# Risks

- **旧规格误解仍可能回流**：若实现或评审仍按「三套控件」理解细致度，会做出手册没有的界面。合同必须把「一套时间轴」写成硬条件。
- **标签字面量大小写**：手册规则是 `Static` / `grasp` / `Place` / `End`（大小写混用）。手册单视角示例里的 `start` / `end` 是占位，不是本轮预置词表。实现不得改成全小写、全中文或另一套同义词。
- **帧率错位**：可变帧率、未声明帧率、或配置帧率与视频不一致会导致区间对不齐。手册单视角示例为 30，2–3 视角正文又写「默认是 24」——本轮不裁定哪一个是平台默认，只要求配置里写明所用帧率并与视频一致。
- **重叠策略因任务而异**：手册同时写了「尽量不重合」和「特殊任务允许」。做成硬互斥会误伤允许重叠的任务；做成默认鼓励重叠又违反一般情况。
- **稀疏工作区无法源码级 UI 回归**：验收依赖官方发行版行为 + 配置 / 导出夹具，存在「文档写了但未在本机源码级点过」的缺口。
- **手册模板里的空 Label / 示例标签**：单视角模板有空 `value`；2–3 视角示例标签是 Movement / Still / Slow Motion，与阶段词表不是同一套。本轮起步模板以规则章节的四字面量为准，不要把示例占位标签抄成产品词表。
- **镜头字段名随数据包变化**：多视角模板若写死 top / left / right，遇到其它字段名会播不出来。说明必须要求对照数据包核对。

# Suggested Verification

本轮**尚未**有 pytest / eval 绿结果。不要假装已经跑绿。上游 README / Makefile 测试不是本轮 overlay 的通过条件。

建议合同与 eval（写入 `docs/harness/evals/`）至少覆盖：

- **配置夹具**：单视角配置 XML 合法，含 `Video` + `TimelineLabels`；预置字面量包含 `Static`、`grasp`、`Place`、`End`；没有第二套「帧级时间轴」冒充细致度。

- **头尾 Static**：同一任务上允许两段 `Static`（片头 + 片尾），不被当成非法。
- **边界**：缺视频字段的任务、空标注、只有整段没有区间——允许或拒绝在合同里写死，禁止实现时猜测。
- **可选 API 冒烟**：有发行版时，用现有 API 建项目或导入示例；失败则报告环境，不为此改 Django。
- **手工冒烟**（有 Docker / 发行版时）：按短说明走通「初步能跑」。稀疏工作区不要求完整 clone。

- **失败行为**：无法完成时返回明确错误；禁止编造手册未写的质检规则、未写的动作词表、或非官方导出字段。
